## Как устроено
| Файл | Назначение |
|---|---|
| `src/forms.mjs` | `POST /api/lead`, `GET/POST /api/reviews`, `GET /api/config`: проверка, лимиты, honeypot, проверка Origin |
| `src/notify.mjs` | канал Telegram (Bot API `sendMessage`), очередь повторов `processDue` |
| `src/portfolio/store.mjs` | таблицы `leads`, `lead_deliveries`, `reviews` (в той же SQLite `DATA_DIR/portfolio.db`) |
- Приём заявок включается `LEADS_ENABLED=1` **и** наличием канала (`TG_BOT_TOKEN`+`TG_CHAT_ID`). Иначе `POST /api/lead` отвечает 503 (как раньше), а кнопки «Оставить заявку» на сайте остаются скрытыми: клиент спрашивает `/api/config`.
- Заявка сначала сохраняется в БД (имя, телефон, комментарий, параметры калькулятора, страница, хеш IP), затем делается попытка доставки. Ответ честный: `saved` (сохранена) и `notified` (хотя бы один канал подтвердил отправку). При сбое статус `pending`, повтор каждые 30 с с нарастающей паузой, после 8 попыток `failed`. Заявка не теряется. Статусы видны в админке (вкладка «Заявки»).
- Защита: согласие обязательно (проверяется и на сервере), проверка `Origin`, только `application/json`, лимит тела 8 КБ, honeypot, лимит запросов в минуту и 5 заявок в час на хеш IP, телефон нормализуется в `+7XXXXXXXXXX`.
- Отзывы сайта: `REVIEWS_FORM=1`. Имя 2–60, оценка 1–5, текст 10–1500, ссылки и контакты отклоняются, не больше 3 в сутки с адреса. Сохраняются как `pending`, публикуются только после «Одобрить» в админке (вкладка «Отзывы»). Вывод на странице только через `textContent` (HTML не исполняется). Рейтинг сайта считается отдельно от Авито.
- Email-отправки нет и не планируется.

## Импорт кейсов портфолио (10 работ, 32 фото)
Данные: `content/portfolio/cases.json` и папки `content/portfolio/<slug>/photo-NN.webp` (реальные фото владельца, с них срезана нижняя полоса с водяным знаком Авито; оригиналы хранятся отдельно у владельца и в репозиторий не входят).
```bash
# на сервере, от пользователя сервиса; DATA_DIR берётся из окружения (на VPS /opt/finikfix/shared/data)
node --env-file=/opt/finikfix/shared/.env scripts/import-portfolio.mjs            # пробный запуск, ничего не меняет
node --env-file=/opt/finikfix/shared/.env scripts/import-portfolio.mjs --commit   # перед этим делается копия базы в DATA_DIR/backups
node --env-file=/opt/finikfix/shared/.env scripts/import-portfolio.mjs --commit --only AV-03   # один кейс
```
- Идемпотентно: кейс ищется по `source_id` (AV-01…AV-10), фото по SHA-256. Повторный запуск ничего не дублирует и не удаляет, правки в админке не перезаписываются.
- Кейс публикуется автоматически только при первом импорте, когда загружены все ожидаемые фото. Скрытое админом остаётся скрытым.
- **Новые фото позже:** положить файлы в `content/portfolio/<slug>/` (порядок по имени; файл `cover.webp` станет обложкой) и повторить `--commit`. Либо загрузить через админку (несколько файлов сразу, порядок ←/→, «Сделать обложкой»).
- Битый файл (не изображение) пропускается с сообщением об ошибке, остальные грузятся, на диске мусора не остаётся; код возврата 1.
- Файлы лежат в `DATA_DIR/uploads` вне релизов: деплой и перезапуск их не трогают.
- Цены кейсов — стоимость уже выполненных работ (на карточке пометка «Не является текущим прайсом»), прайс сайта не менялся.
- Правки текстов относительно `portfolio-manifest.json`: AV-02 «плохо обслуживания» → «плохого обслуживания»; названия AV-04 и AV-06 уточнены словами «нет изображения (HDMI)» и «перегрев»; в AV-07 «TMP» исправлено на «TMR», а фраза «Гарантия 24 месяца» **не опубликована** (на сайте везде 90 дней, правило 3 из AGENTS.md; решение за владельцем). Оригинальные тексты сохранены в `source_title`/`source_description`.

## Обслуживание сервера через GitHub Actions (2026-11-05)
Пользователь `deploy` не root. Чтобы импорт, секреты и nginx выполнялись из Actions без раздачи root, используется помощник `deploy/finikfix-ops` (root:root, deploy его менять не может; sudo разрешён только на него). Подкоманды фиксированные: status, backup, import-portfolio, import-reviews, set-secret (только TG_BOT_TOKEN, из stdin), set-env (белый список ключей), gen-salt, tg-check, tg-test, nginx-lead open, verify-data.

**Разовые действия владельца:**
1. На сервере от root установить помощник. Установщик скачивает два файла и ставит их, только если SHA-256 совпадает с зашитым в нём; сам установщик проверьте командой `sha256sum -c` (контрольную сумму установщика даёт Claude в сообщении; она же вычисляется из файла в репозитории):
   ```bash
   curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/pavelvladimirovich258614-sys/sayt_finik_fix/claude/epic-hypatia-mxxztu/deploy/install-ops-helper.sh -o /root/install-ops-helper.sh
   echo "<SHA256>  /root/install-ops-helper.sh" | sha256sum -c - && less /root/install-ops-helper.sh && bash /root/install-ops-helper.sh
   ```
2. В GitHub: Settings → Secrets and variables → Actions → New repository secret `TG_BOT_TOKEN` (новый токен бота после /revoke). Значение не показывается в логах.
3. Оба получателя (1274132933, 1831192124) нажали `/start` у @uved_nikita_bot.

**Операции** (Actions → Server Ops FinikFix → Run workflow, либо push в ветку `ops/<операция>`): `probe` (без sudo), `status`, `backup`, `import-dry`, `import-commit`, `tg-setup`, `tg-test`, `enable-reviews`, `enable-leads`, `test-lead`, `verify`. Деплой: workflow «Deploy FinikFix» (вручную) либо push в ветку `release/production` (только коммит, уже входящий в `claude/epic-hypatia-mxxztu`).
Порядок: deploy → import-dry → import-commit → tg-setup → tg-test (подтвердить получение) → enable-reviews → enable-leads → test-lead → verify. `enable-leads` не включится без успешной проверки бота (`tg-check`).

**Безопасность помощника (проверено 2026-11-05).** Фиксированные подкоманды, без `eval` и произвольных путей; блокировка в `/run` (каталог `/opt/finikfix` доступен на запись пользователю `deploy`, поэтому lock там был бы уязвим к подмене символической ссылкой); токен принимается только из stdin в проверенном формате и не печатается; список ключей `set-env` ограничен (`TG_CHAT_ID`, `REVIEWS_FORM`, `LEADS_ENABLED`); админка помощником не включается. Остаточный риск: `import-*` и `tg-*` запускают код текущего релиза от пользователя `finikfix`, а релиз выкладывает `deploy`; это тот же уровень доверия, что у самого сервиса, который уже исполняет код этого релиза. Удаление заглушки nginx: `deploy/nginx_lead_block.py` (разбор скобок с учётом кавычек и комментариев; удаляется только блок с `return 503`), копия конфигурации в `/opt/finikfix/backups`, `nginx -t`, автоматическое восстановление при ошибке теста или перезагрузки.

## Результат запуска на VPS (2026-11-05)
- Помощник `finikfix-ops` установлен (проверено `status`: релиз `4347949`, 32 фото, копия БД `pre-seed-…`).
- `tg-setup`: `TG_CHAT_ID` и `IP_SALT` записаны, токен принят проверкой формата. `getMe` с сервера: **fetch failed**.
- Диагностика `net` с VPS 194.34.239.218: `api.telegram.org` (149.154.166.110, IPv6 2001:67c:4e8:f004::9): DNS отвечает, TCP-соединение не устанавливается (таймаут 10 с, порт 443 закрыт или фильтруется). Доступны: `api.github.com`, `dev.max.ru` (200), `platform-api.max.ru` (404 на корне, TLS ок).
- **Вывод:** с этого хостинга Telegram Bot API напрямую недоступен. Формы заявок остаются выключены (`LEADS_ENABLED` не задан, `/api/lead` закрыт nginx). Варианты: (1) канал MAX (API доступен с сервера; нужен токен бота MAX); (2) обратный прокси Bot API вне РФ по HTTPS и переменная `TG_API_BASE` (поддержка в коде есть, нужно добавить ключ в белый список `finikfix-ops set-env` и переустановить помощник); (3) исходящий HTTPS-прокси для Node (`NODE_USE_ENV_PROXY`, Node ≥ 22.21).
- Отзывы сайта (`REVIEWS_FORM`) не включены: для модерации нужна админка (`ADMIN_ENABLED=1` и создание администратора на сервере), иначе отзывы копились бы без возможности опубликовать.
