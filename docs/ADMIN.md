# Админка FinikFix: статус, план и требования

> **Статус: ЗАПЛАНИРОВАНА И ВХОДИТ В ПРОЕКТ. НЕ ОТМЕНЕНА.** Реализована частично (портфолио, отзывы, заявки), на production выключена. Остальной объём (цены, тексты, страницы) не реализован, но остаётся требованием заказчика. Не удалять, не считать устаревшей, не заменять сторонней CMS без решения владельца. Источники: ТЗ v3.0 (`AGENTS.md`, разделы «Технический стек» и «Приёмка»), `docs/PORTFOLIO-ADMIN.md`, `docs/LEADS.md`, `deploy/VPS.md`.

## 1. Зачем
По ТЗ заказчик (Никита Филиповский) **сам** правит цены, тексты, фото, страницы и смотрит заявки; админка на русском. Приёмка: «Заказчик сам меняет цены и тексты в админке». Цены нельзя хардкодить в вёрстку, они должны жить в редактируемом источнике (сейчас они в `src/data.mjs`, это временное решение, см. п. 4).

## 3. Требования
### 3.1 Доступ и включение
- Выключена по умолчанию. Работает только при `ADMIN_ENABLED=1` **и** по HTTPS (за nginx с `X-Forwarded-Proto: https`); по HTTP `/admin` и `/admin/api` отвечают 404.
- Администратор создаётся только из консоли сервера (`scripts/create-admin.mjs`): пароль вводится скрытно, не короче 12 символов, пароля по умолчанию нет. Повторный запуск с тем же email меняет пароль и закрывает старые сессии.
- Включение/выключение на production: операция `enable-admin` (Server Ops) или вручную по `deploy/VPS.md`. Порядок: домен и HTTPS, деплой, создание администратора, `ADMIN_ENABLED=1`, снять запрет `/admin` в nginx, блок `/admin/api/` с лимитом 32 МБ.
- Язык интерфейса: русский.

### 3.2 Защиты (уже реализованы, не ослаблять)
- Пароли: scrypt (`node:crypto`).
- Сессии: cookie `ff_sid`, HttpOnly, Secure, SameSite=Strict, 12 часов; в БД только хеш токена.
- CSRF: токен сессии в `X-CSRF-Token` + проверка `Origin`.
- Подбор пароля: не больше 5 неудач за 15 минут на IP (по `X-Real-IP`) и на email.
- Загрузка файлов: проверка реального типа (JPEG, PNG, WebP) по magic bytes, до 8 МБ на файл, 10 файлов за запрос, 20 фото на работу, до 10000 px; случайные имена, обход путей невозможен; файлы отдаются с `nosniff` и `sandbox`; из JPEG удаляются EXIF/XMP и геометки.
- Без авторизации `/admin/api/*` отвечает 401.
- Независимого аудита безопасности не проводилось.

### 3.3 Сопутствующие требования
- Данные вне релизов: `DATA_DIR` (`/opt/finikfix/shared/data`): `portfolio.db` и `uploads/`; обновления сайта их не затрагивают.
- Ежедневный бэкап (`deploy/finikfix-backup.sh`): согласованная копия БД (`VACUUM INTO`), фото, заявки, настройки; 14 архивов. Автобэкапы входят в жёсткие требования ТЗ.
- Российский хостинг, данные на серверах в РФ (подтверждение местоположения VPS открыто, см. `docs/LEGAL-TODO.md`).
- Модерация отзывов: форма отзыва (`REVIEWS_FORM=1`) включена, отзыв сайта публикуется только после одобрения в админке (без админки отзывы копятся).
- Заявки: `LEADS_ENABLED=1`; уведомления только через MAX (Telegram с сервера недоступен); админка показывает статус доставки.
- Правила содержимого, которые админка не должна нарушать (`AGENTS.md`, «Жёсткие правила»): гарантия везде 90 дней (исключение AV-07), цены только с «от», точный адрес не показывать, ссылок на Авито нет, паспортные данные не публиковать.
- Тесты: `test/portfolio.test.mjs` (авторизация, CSRF, загрузка, права, публичное API), `test/forms-import.test.mjs`. Любое изменение админки сопровождается тестами; CI = `npm run build` + `npm test`.
- Секреты (токены, пароли) не хранятся в git, не пишутся в логи и чат.

## 4. Не реализовано и требует решения (не додумывать)
1. **Как заказчик правит цены и тексты.** ТЗ требует, но механизма нет: цены в `src/data.mjs`, сайт собирается статически. Варианты (хранить в БД и пересобирать, отдавать динамически, и т.п.) не выбраны. Нужно решение владельца и исполнителя.
2. Какие тексты и страницы должны быть редактируемыми (все, отдельные блоки, только цены).
3. Роли и число администраторов (сейчас предполагается один; email в `deploy/VPS.md` приведён как пример команды).
4. Восстановление пароля (сейчас только повторный запуск скрипта в консоли сервера).
5. Двухфакторная защита, ограничение по IP, журнал действий администратора: в репозитории не определены.
6. Поведение при ошибках в админке и откат правок текстов/цен: не определено.
7. Управление слайдами Hero и фото категорий из админки: не определено.
8. Лимит заявок `POST /api/lead` использует `X-Forwarded-For` (подделывается): перейти на `X-Real-IP` (отмечено в журнале `AGENTS.md`).
9. Независимый аудит безопасности перед публичным включением.
